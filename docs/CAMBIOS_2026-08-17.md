2. CARPETAS DE DATOS POR EMPRESA — AHORA SON IDENTIFICABLES
   - Las carpetas de balanzas/catálogos cifrados en data/ se llaman
     empresa_<id> (empresa_1, empresa_2…) y así se quedan: el id es estable,
     el nombre de la empresa puede cambiar, traer acentos o repetirse entre
     dos empresas, y usarlo como nombre de carpeta arriesgaría archivos.
   - Se agregó backend/dataStore.js → actualizarIndiceEmpresas() /
     quitarDeIndiceEmpresas(), llamado automáticamente al crear, editar o
     borrar una empresa (backend/src/models/empresasModel.js). Mantienen
     data/_empresas.txt con el mapeo legible, por ejemplo:
       empresa_1 = Grupo XYZ SA de CV
       empresa_2 = Comercializadora ABC
   - Al arrancar, server.js reconstruye ese archivo desde la base de datos
     (reconstruirIndiceEmpresas), así que también cubre las empresas que ya
     existían antes de este cambio.

3. INICIAR.BAT — DETECTA node_modules ROTO DEL BACKEND
   - Antes solo instalaba dependencias si backend/node_modules NO existía.
     Si esa carpeta se copiaba de otra PC o quedaba de una versión distinta
     de Node, el BAT nunca la reinstalaba y el servidor truena al arrancar
     (better-sqlite3 es un módulo nativo, compilado para una versión de
     Node/SO específica).
   - Ahora, si node_modules ya existe, se hace una prueba rápida
     (`require('better-sqlite3')`); si falla, se borra y se reinstala solo,
     antes de intentar levantar el servidor.

4. DIAGNÓSTICO: "puerto 3000 vacío / ERR_CONNECTION_REFUSED"
   - No es que la base de datos se haya quitado del proyecto: orangematch.db
     nunca viajó en el ZIP (está en .gitignore a propósito, para no mezclar
     datos de una instalación con otra) — backend/src/models/db.js la crea
     sola, vacía, la primera vez que el servidor arranca bien.
   - ERR_CONNECTION_REFUSED significa que NADA está escuchando en el puerto
     3000 — o sea, el proceso de Node truena ANTES de llegar a app.listen().
     La causa más común con este proyecto es exactamente el punto 3: un
     backend/node_modules incompleto o compilado para otra versión de Node.
   - Ver instrucciones de diagnóstico manual en el README, sección
     "Si el puerto 3000 no responde".
